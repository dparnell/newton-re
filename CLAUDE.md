# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A reverse-engineering project for the Apple Newton MessagePad 2x00 (ARM StrongARM SA-110, big-endian, NewtonOS 2.x), aiming eventually at a retargetable re-implementation. Two debug ROMs are in `DebugRom/` and the tooling works with either; `src/` is a reconstruction of the US English one, `MP2x00 US` (2.1, build 717006), because the owner does not read German and the `MP2100 D` image (D-2.1, build 747129) has no English locale and German strings built into its extension's applications. Switching which ROM `src/` is of is `analysis/recite.py` for the citations, `analysis/regenerate.py` for the generated tables, and the three `NEWTON_ROM*` lines at the top of `src/CMakeLists.txt`. It holds the ROM images, the Newton Driver Developer Kit (DDK) headers (`headers/` — struct and class declarations to use when reconstructing types), documentation, and our own tooling under `tools/newton-rom/` that extracts the ROM, demangles the debug symbols and builds an annotated Ghidra project.

**Project rule (from the owner):** every tool used in the process must live in this repo, be fully documented (purpose, inputs, outputs, exact invocation) and be reproducible by others from a clean checkout. Don't leave analysis in scratch scripts — promote it into `tools/` or record the finding in a README/test.

## Commands

All tooling is Python 3.9+; the header step needs `libclang` (`tools/newton-rom/requirements.txt`) and the Ghidra step needs `pyghidra` (bundled with Ghidra 11.3+). Ghidra 12.1.3 is installed at `D:\apps\ghidra_12.1.3_PUBLIC`; a venv with pyghidra lives in `build/venv` (git-ignored, recreate with the commands in `tools/newton-rom/README.md`).

```powershell
# whole pipeline: rom.bin + layout.json + symbols.json + Ghidra project build/ghidra/MP2x00US.gpr
build\venv\Scripts\python tools\newton-rom\pipeline.py "DebugRom\MP2x00 US" -o build\MP2x00US --name MP2x00US --ghidra D:\apps\ghidra_12.1.3_PUBLIC [--no-analyze] [--no-ghidra]

# individual steps
python tools\newton-rom\extract_rom.py "<image>" --rex "<high>" -o build\MP2x00US
python tools\newton-rom\dump_symbols.py "<image>" -o build\MP2x00US\symbols.json --text build\MP2x00US\symbols.txt
build\venv\Scripts\python tools\newton-rom\parse_headers.py headers -o build\MP2x00US\types.json
build\venv\Scripts\python tools\newton-rom\ghidra_scripts\import_rom.py build\MP2x00US --project build\ghidra --name MP2x00US --ghidra <ghidra> --no-analyze
build\venv\Scripts\python tools\newton-rom\ghidra_scripts\verify_types.py build\MP2x00US --project build\ghidra --name MP2x00US --ghidra <ghidra>   # -> romfacts.json, verify-report.txt
build\venv\Scripts\python tools\newton-rom\ghidra_scripts\apply_romfacts.py build\MP2x00US --project build\ghidra --name MP2x00US --ghidra <ghidra> --analyze
build\venv\Scripts\python tools\newton-rom\ghidra_scripts\check_import.py --project build\ghidra --name MP2x00US --ghidra <ghidra> --lookup <Name>... --type <Struct>...

# tests (unittest, no pytest needed; oracle test uses the US ROM + tools/mpdumper output)
python tools\newton-rom\tests\test_demangle.py
python tools\newton-rom\tests\test_rom.py
build\venv\Scripts\python tools\newton-rom\tests\test_headers.py
```

The import step refuses to overwrite an existing program of the same name — delete `build/ghidra` (or use another `--name`) to re-import. Import ~40 s, verification ~1 min, auto-analysis ~4 min.

## Architecture of the tooling (`tools/newton-rom/`)

Pipeline: `extract_rom.py` → `dump_symbols.py` → `parse_headers.py` → `ghidra_scripts/import_rom.py` → `verify_types.py` → `apply_romfacts.py`, glued by `pipeline.py`. The library `newtonrom/` has one module per concept: `aif` (container), `symbols` (debug table), `rex` (ROM extension), `jumptable` (virtual↔physical slot maths + verification), `demangle` (parser producing a type AST, rendered to text *and* JSON), `headers` (libclang extraction of the DDK headers into the same JSON type schema, plus `HeaderTypes` prototype matching), `ghidra_import` (consumes layout.json + symbols.json + types.json; only imports Ghidra classes inside functions so the rest works without Ghidra). `ghidra_scripts/NewtonROMImport.py` is a thin PyGhidra Script-Manager wrapper around `ghidra_import.apply`.

Key facts the code relies on (all asserted by `tests/test_rom.py`; details in `tools/newton-rom/README.md`):
- Physical ROM = `RO ‖ RW-init ‖ REx`; REx `start` == `ROM$$Size`. RW data lives in RAM at 0x0C100800.
- Debug area is one `LANG_NONE` section: names + addresses only, **no types**; flags are unreliable (data marked as code).
- Patchable jump table: physically at ROM 0x2000, virtually at 0x01A00000 with 32 slots per 4 KB page in a diagonal alias layout; branch offsets are relative to the *virtual* slot address. Each exported function has a body symbol and a same-named slot symbol; `dump_symbols.py` verifies all slots resolve.
- Demangling is cfront/ARM style; nested-list back-references inherit the enclosing list (documented in `demangle.py`). Our output matches libiberty exactly on all 52,751 US symbols it handles — keep `tests/test_demangle.py` green when touching the demangler.
- DDK header layout: Apple's ARM C++ put the vptr at offset 0 and gave empty bases no space (verified on `TAEventHandler`/`TUObject` constructors), so clang's layout (`armeb`, `-mabi=apcs-gnu`) is used as-is; bit-fields are MSB-first (verified on `TCardPCMCIA::AddFuncSpecificCIS`). The MP2x00 US config is `forQ __arm` (a localised ROM adds its language: the MP2100 D is `forGerman` on top of these); V1 headers (`CommToolProtocol.h`, `SerialChip.h`) and `.f.h` files are excluded. Known header/ROM differences: `TCardDevice`, `TObjectIterator`, `TCMOSerialChipSpec` (see `verify-report.txt`).
- Constructors self-allocate (`teq r0,#0; bne; mov r0,#size; bl operator_new`) and store the vtable at [this,#0]; `verify_types.py` reads sizes/vtables from them into `romfacts.json`. Vtables are arrays of `B` instructions in declaration order (dtor first, base entries first); virtual calls are `mov lr,pc; add pc,rN,#slot*4`, which Ghidra treats as a terminal jump — `fix_virtual_calls` marks them fall-through calls (`FlowOverride.CALL`), otherwise functions are truncated after their first virtual call (`ghidra_scripts/fix_virtual_calls.py` re-marks an older project's sites).
- Header/symbol matching resolves typedefs first (`Boolean`→`Uc`, `RefArg`→`RC6RefVar`); a unique match supplies return type and parameter names. Plain-name symbols are matched to `extern "C"` declarations by name.
- Ghidra: language `ARM:BE:32:v4`, compiler `apcs`; there is no `__thiscall` on ARM, so member functions get an explicit `this` parameter. Unknown classes passed by value make the prototype unsafe, so those functions get name + comment only.
- Don't name a directory `ghidra` anywhere on `sys.path` — it shadows the Java `ghidra` package under PyGhidra (hence `ghidra_scripts/`).

## Reconstructed source (`src/`)

Organised by functional area (`os600/kernel`, `os600/user`, `hal/`, `utility/`, `frames/`, …) — never by ROM address — because the owner wants to retarget the OS to other hardware and run the user-mode side on other host OSes: hardware code goes behind `hal/`, the user-side API talks to the kernel only via an explicit syscall interface. Conventions (see `src/README.md`): keep Apple's names and layouts; every reconstructed function has a `// ROM 0x<addr> <mangled>` citation (checked by `tools/newton-rom/analysis/coverage.py build/MP2x00US --check`); each unit has a host test. `src/ddk/` is generated by `tools/newton-rom/sync_ddk_headers.py headers src/ddk` (CLibrary headers excluded; `Protocols.h` and `BufferSegment.h` replaced by the reconstruction's own; a short list of documented patches) — regenerate, don't edit. Protocols (Newton's interface/implementation mechanism, `PROTOCOL TFoo : public TProtocol`) are re-expressed portably in `src/protocols/Protocols.h` — interface methods are virtual, `TClassInfo` holds function pointers, `PROTOCOL_CLASSINFO` makes an implementation's class info; `analysis/classinfo.py build/MP2x00US --name TFooImpl` decodes a ROM implementation's table (dispatch slots, monitor selectors by name), `--all` lists all 101 (`docs/protocols/`). Constant tables from the ROM go through `analysis/romtable.py build/MP2x00US NAME[:type[:count]]... -o file.cpp` (never typed in by hand; `cstr` for string-pointer tables, tables in the initialised RAM area are read from the ROM's copy). Words of persistent formats (packages, stores, compressed chunks) are big-endian on every host: read/write them with `toolbox/ByteOrder.h`, not by casting.

The frames object system (`src/frames/`, `docs/frames/README.md`) keeps the ROM's object layouts with pointer-sized Refs and header words (`frames/ObjHeader.h`, `ObjectHeap.h`); its constants (the ROM's RSSYM symbols and R/RS objects, the object area's whereabouts) come from `analysis/romconstants.py build/MP2x00US -o src/frames` (generated, do not edit), and `frames/ROMImport.cpp` reads the ROM's own 46538 objects out of a ROM image into the host layout (`test_ROMImport` uses the image in `DebugRom/`). `objects.h`'s `Ref` is made pointer-sized by the sync patches. The NewtonScript interpreter (`frames/Interpreter.h`, `Interpreter.cpp`, `VariableLookup.cpp`) runs bytecode as the ROM's `TInterpreter::SlowRun` decodes it; native built-ins are bound by C symbol name to the ROM's native function table (`frames/NativeFunctions.h`, `ROMNatives.cpp` generated by `analysis/nsfunctions.py build/MP2x00US --natives`; `--disasm NAME` disassembles a ROM NewtonScript function), and `InitObjects` starts the interpreter as the ROM does. Test bytecode is assembled with the `Asm` class in `frames/tests/test_Interpreter.cpp`. The host's pen is `hal/host/HostTablet.h` (`HostTabletPenDown/Move/Up`, or queued records fed one per tick of a `Wait` through `gHostWaitHook`, the inker task's stand-in). `test_Views`'s `TestClicks` taps and drags a view. `EdgeList.h` is the gesture domain (`TEdgeListDomain`, 'SCRB' - the first domain above the strokes and the one every level installs): a stroke is reduced to the corners of a polyline (a recursive splitter, then `Collapse2`) and `TestLine`/`TestCarets`/`TestScrub` say what it is, which `TScrubRecognizer` turns into aeLine, aeCaret, aeScrub or aeTap for the view's `viewGestureScript`; the angles they are all measured in are `toolbox/Angles.h` (16.16 degrees in (-180, 180], `AngleFromSlope` over the tables of `AngleTables.cpp`). A paragraph answers all three pen commands: the scrub (`HandleScrub`/`ScrubLines`/`ScrubWords`), the caret (`HandleCaret` over `InsertHorizontalSpace`, `InsertVerticalSpace` and `CheckAndDoJoin`) and the line (`HandleLineGesture`, the case change). The word domain is `WRecDomain.h` (`TWRecDomain`, 'WREC': it takes strokes and hands every question to a `TWRecognizer`, the protocol a handwriting engine plugs into - the engine calls back through the protocol's own methods, which is where the grouping lives), the units it works in are `WordUnit.h` (`TStdWordUnit`/`TRecUnit`/`TWRecUnit`: interpretations carrying a word), the readings are `WordList.h` (`TWordList`, sixteen of them packed into one handle with 0xFFFF between them, out of a pool of twelve; plus the try string and `Reorder`, which moves the '0'/'O' and '1'/'l' guesses by what the writer has lately been choosing by hand), what a script is told about a piece of writing is `WordInfo.h` (`MakeWordInfo`: protoWordInfo cloned with the unit's type, the readings, the strokes as a bundle and the ink flag), and the engine itself is `InkRecognizer.h` (`TInkOnlyRecognizer`, which gathers strokes into words and says it cannot read any of them - the ROM's own is the CIC handwriting library, NOT YET; the host registers this one and `SetWordRecognizer` puts it in use). `Recognizer.h`'s `TWRecRecognizer`/`InstallWRecRecognizer` put it on the recogniser list, and `WordRecognizerHandleUnit`/`GetInkCommand` decide what the view under the writing is sent: aeTap, aeWord, or one of the two ink commands. The shape domain and a recogniser that reads anything are NOT YET. Ink is `src/ink/` (`docs/ink/README.md`): `Ink.h` is what ink is - the three classes of binary (`IsInk`/`IsRawInk`/`IsOldRawInk`/`IsInkWord`: 'ink, 'ink2 and 'inkWord) and the eight bytes an ink word carries after its strokes (`PackedInkWordInfo`: the width, ascent, descent, x-height, pen size, face and scale, opened out by `ExpandPackedInkWordInfo` into an `InkWordInfo` with the font size the x-height comes to, the pen that size wants and the measurements at the word's scale), which is what lets an ink word be laid out among real characters without being expanded. `InkCodec.h` is the boundary between the operating system and the codec that packs the strokes - the ROM's own seam, made explicit so a modern codec can be registered beside the ROM's (`TInkCodec`, `RegisterInkCodec`, `InkCodecFor` choosing one per object by `GetInkFormat`); a decoder hands its points out through a callback, as the ROM's three sinks do. `CICCodec.h` is the ROM's codec (the CIC handwriting library's): the bit reader, the two code books (eight tables each, found by walking their sizes; `InitializeParagraphCompression` points at the ROM's own `Rparagraphcodebook1`/`2` binaries), the entropy decoder (`DecodeWord_OLD`/`DecodeWord_NEW` over `CICTables.cpp`, generated), `ReadNewStroke`, the short stroke, the long stroke's curved segments (`ReadSegmentNear`/`RestoreSegment`, seventeen points by forward differences) and the two point thinners. The encoder is there too (`EncoderOpen`/`Run`, `WriteLongStroke`, the segment fitting `TestStrokeSeg`/`Repar`/`RFFT_9_4`/`RIFT_4_9`/`Tracing` and the rounding `SegVectQuant`), so ink round-trips; `TInkCodec::Encode` takes a source of points rather than a list of strokes, as the ROM's own encoder does. `InkStrokes.cpp` is where the strokes and the codec meet (`InkCompress`/`InkExpand` over `PGCGetPointProc`/`PGCStorePointProc`, the only part of the area that knows what a stroke is), with `TStrokesToInk`/`TStrokesToInkWord` (the strokes moved to the origin and the box they came from answered; a word first brought down to a size a line of text can hold), `InkBounds` and `InkDraw`/`InkDrawScaled`. An ink word's measurements are `GetPackedInkWordInfoFromStrokes` over the word recogniser's baseline finder (`recognition/Words.h`'s `FindBaseline`, which takes the ROM's own fallback path while `low_level` is NOT YET).  `InkShapes.h` is ink as a shape frame - the form `views/DrawShape.h`'s `MakePolygonForm` makes for the ink verb, which `DrawOneShape` draws out of its `originalBounds` and into its `bounds` - with `GetPolyAsTStrokes` opening one back up, `SplitInkAt`/`MergeInk` cutting a word in two at a caret and joining two (both all the way down to the strokes and back), `AddInk` handing a shape to an edit view, `StrokeBundleToInkWord`/`CompressStrokes`/`ExpandInk` between ink and the recogniser's stroke bundles, and `NextInkIndex`/`GetInkAt` for the ink words a paragraph keeps in its text.  `TEditView::HandleInk`/`HandleInkWord` and the `aeRawInk` command are the view side (`views/EditView.h`); `TNotebook::InitToolbox` starts the codecs and the code books (DEVIATION: the ROM does it in `TRecognitionManager::Init`, which is below the ink area here).  `InkFont.h` is an ink word standing in for a font, which is how a word of writing is drawn inside a line of text: `views/ParagraphView.h`'s `CreateParagraphStyleRecord` puts the `'inkWord` binary where a font family would be, `qd/Fonts.h`'s `OpenFont` sees it there and hands it to `InkOpenFont`, and the FontEngineInfo that comes back has the word's own measurements as its line metrics and one glyph - `TInkWordGlyph`, which works out what the word measures at the size and face asked for and draws it into a bitmap the text engine blits (the space is a blank glyph a fifth of the line height wide).  A rich string's own ink draws the same way (`qd/Text.h`'s `DoRichString`, over `TRichString::GetLengthsAndDataInRange`): the range is cut into text and ink runs and an ink run's style carries the address of its blob, which is what the integer form of an ink word in `InkOpenFont` is for.  **Writing is kept**: a stroke drawn on a page is claimed by the word domain, found to be unreadable, and put down by `TEditView::RealDoCommand`'s `aeInkWord` case as a paragraph of one ink word (`src/host/demo/ink.ns` takes a picture of it with the pen down and another after the recogniser has finished; the route across the five areas is `docs/ink/README.md`'s "From the pen to ink on the page"). `TEditView::AddNewParagraph` places it as wide as the word measures at its own scale and one line tall, from the middle of the box it was written in - the ROM's own arithmetic - and `qd/Fonts.h`'s `CreateTextStyleRecord` puts the word where the family goes so the ink font engine opens it. A page whose caret is in one of its own paragraphs takes the word into that paragraph instead, through `TParagraphView::HandleInsertItems` (the command 0x4d a paragraph answers for everything put into it from outside - a recognised word, a dropped clipping, the halves of an ink word cut in two by a caret (`CheckAndDoSplitInk`) - gathering the items into one `aeReplaceText` with a delimiter worked out between each pair). The corrector, `TParagraphView::HandleWord` and the printing path's outlined paths are NOT YET. The application layer is `src/newt/` (`docs/newt/README.md`): `NewtWorld.h` - `TNewtWorld`, the 'newt app world the loader's 'main' task runs (`NewtInstallUserMain`), its boot (`MainConstructor`, `PreMain`) and `TNewtEventHandler` taking the 'newt events ('idle: the application's Run; 'keyb; 'draw; 'scpt: `TRunScriptEvent` runs a root variable's method) - and `Notebook.h` (`TNotebook`/`TARMNotebook`, `gApplication`: the root view, the toolbox, the idle passes, the notifiers). `test_Newt` boots the OS and drives the world through its port; `gNewtHostBoot` = `HostBootNewtWorld` (`host/HostViews.h`) reads the ROM image in and makes the display inside the world. `build/host/host/newton [--rom image] [--display WxH[xdepth]] [--scale n] [--script file.ns] [--headless seconds]` is the OS running interactively: a window on the display (`host/win32/HostWindow.cpp`, Windows only; built without the Newton include paths - `src/intl/Locale.h` shadows `<locale.h>` on a case-insensitive file system), the mouse as the pen, the keys as the keyboard (`host/HostKeyboard.cpp`, a task sending 'keyb events like the keyboard tool), `hal/host/HostTablet.h`'s inker task reading the tablet buffer every tick; `--script` runs a file as the ROM's PreMain runs its bootTestScript (`src/host/demo/newton.ns`); a script's `ScreenSnapshot` writes the display (a delayed action, the boot's splash gone by then). `qd/RegionVars.h` has the region holders (`TRegionVar` registers an exception cleanup so a Throw gives its region back). - the ROM is built with `QD_Gray` (a `PixelMap` has the `grayTable`, a `GrafPort` is 0x54 bytes) and its `Region`/`Picture`/`Polygon` have their `Rect` at offset 4 (APCS word alignment): sync patches fix the DDK structs; the heap compacts handles, so a pointer into a handle's block is stale after any allocation. `frames/UnicodeTables.h`'s `InitUnicode` (run by `InitObjects` when the ROM's objects are imported) installs the ROM's `unicode` frame's character tables into `utility/Unicode.h`: the Mac Roman encoding each way (`TEncodingMap`, `InstallCharEncoding`), the case and diacritical tables (`UppercaseText`, `LowercaseText`, `NoDiacriticsText`), the break table (`IsDelimiter`); without them the host's Latin-1 fallbacks apply.  Strings are handled through `frames/RichString.h` (`TRichString`, whose ink region keeps a blob per ink character of the text - `GetInkData`, `CloneInkWordNo`, `MungeRange` moving each blob with its character, `CompareInkProc` comparing two ink words by their bytes); text is collated through `frames/SortTables.h` - a sorting table (`TSortingTable`) is a binary of projection entries saying what each character sorts as (its primary weight) and how it differs from the others sharing it (the second order: the cases and the diacriticals), reached through ranges, a binary-searched table of single characters, and a ligature table for the characters that are really two; `TSortTables` (`gSortTables`) holds five of them and the default one (`GetSortID`/`SetSortID`), the ROM's own being the 'unicode frame's `sortTables`, registered by `InitUnicode`; `CompareUnicodeText` walks two strings through it a character at a time and answers the sign of the first difference in the primary weights, an exact compare then asking the second order, and with no table at all `OldCompareText` folds through the Mac Roman character classes instead; `TSortingTable::ConvertTextToLowestSort` is what a soup index stores so its keys compare with a memcmp; the sort/search natives compare through `TGeneralizedTestFnVar` in `frames/ArrayNatives.cpp`. Sound codecs are `src/sound/` (`docs/sound/README.md`): `IMACodec.h` is the IMA/DVI ADPCM the Newton records sound with (`CompressIMA`/`ExpandIMA`/`CheckState` over the standard step and index tables, 0x40-sample blocks with a big-endian header; `test_IMACodec` round-trips a signal and cross-checks an independent decoder); `SampleConvert.h` is the two 8-bit codings 16-bit linear sound is turned into and back from - offset-binary "standard" 8-bit, and mu-law (G.711's shape but on a 14-bit magnitude biased by 33); both decoders dither the bits they cannot carry with QuickDraw's `Random`, so `sound` links `qd`, and the mu-law coder never clamps, so the loudest samples overflow the exponent search into a sign flip or into silence (bugs kept and asserted by `test_SampleConvert`). `Resample.h` holds both rate converters: `Resample`, the nearest-neighbour one the sound DMA channel puts a buffer through (a `SampleSpec` of the two buffers, rates and sample sizes plus an optional per-sample converter), and `ResampleFiltered` over a `ResampleState` - a windowed sinc of 261 points at thirteen to the zero crossing (`ResampleTables.cpp`, generated), interpolated between neighbours, the step scaled by the ratio when converting down, with a 160-entry history so a stream converted in pieces comes out the same as one converted whole; at the same rate in and out it is an exact identity delayed by ten samples, which is what `test_ResampleFiltered` pins it to. `SoundCodec.h` is the `TSoundCodec` protocol a sound channel turns coded sound into samples through - a `CodecBlock` describes the buffer, `Produce`/`Consume` work it a chunk at a time, `BufferCompleted` says when it is used up, and the `SafeCodec*` wrappers turn a Throw out of a codec into an error - with `TMuLawCodec` and `TIMACodec` (IMA/DVI ADPCM over `IMACodec.h`, its predictor carried across calls) as the implementations and `InitializeSound` registering them (`test_SoundCodec` boots the OS, the registry being a monitor). `sound/SoundSettings.h` is the volume as a script sees it - `VolumeToDecibels`/`DecibelsToVolume` between the five settings and the server's 16.16 decibels (an eighth, a half and a root half of full amplitude for 1, 2 and 3), and the `GetVolume`/`SetVolume`/`GetSystemVolume`/`SetSystemVolume` natives over `sound/SoundChannel.h`'s `TUSoundChannel`, of which only the state it keeps (the volume, input gain and output device) and the `SendImmediate` that would carry it to the sound server are reconstructed - which is what the ROM's NewtonScript boot needs, its last act being to set the system volume (DEVIATION: with no sound server the host's `GlobalSoundChannel` leaves the channel unopened, where the ROM would throw, so the volume it is told is the volume it answers). `TGSMCodec`/`TDTMFCodec`, `TFrameSoundChannel` and the rest of the `TSoundServer`/`TSoundChannel` layer are NOT YET. `utility/CRC16.h` is the two CRC-16 accumulators framed data is checked with - `TCRC16` (CRC-16/ARC, the nibble tables `kCrc16HTbl`/`kCrc16LTbl`) and `TIrCRC16` (the IrDA/HDLC FCS, CRC-16/CCITT over `IrCRCLookupTable`); the tables come from `romtable.py` (`CRC16Tables.cpp`) and `test_CRC16` checks both against the standard "123456789" values. `utility/RingBuffer.h` is `CRingBuffer` (over the abstract `CBaseRingBuffer` the pipes hold, whose virtuals are declared in the ROM's vtable order - `analysis/vtable.py`), the byte ring buffer the serial/comm code streams through - Put/Get/Peek/Next/Skip, the bulk CopyIn/CopyOut and the Compute*Vectors/Update*Vector runs that cross the wrap, one slot kept free to tell full from empty, and the `CopyIn` that has a `CPipe` read straight into the free runs - and `CRingPipe`, the pipe over such a buffer (a read that empties it asks the subclass's `Underflow` for more, a write that fills it asks `Overflow` to make room; it does not seek); `test_RingBuffer` fills, drains, wraps and bulk-copies the buffer and drives a pipe whose Underflow/Overflow move bytes to and from arrays; `CShadowRingBuffer` is the same buffer with its bytes in a shared-memory object (every byte through `TUSharedMem::CopyToShared`/`CopyFromShared`, the vectors being offsets rather than addresses) plus a speculative read position - `TempGetn`/`TempCopyOut` read ahead without consuming, `TempReset` puts it back - and the block must be made with `kSMemNoSizeChangeOnCopyTo`, or it shrinks to the last write's end whenever the buffer wraps (`test_ShadowRingBuffer`, which boots the OS for a real shared-memory object). `CRingBuffer::MakeShared` hands the buffer's own memory out as such an object (adding `kSMemNoSizeChangeOnCopyTo` to the permissions, which is where that rule comes from) and `UnShare` takes it back - the pair CTaskPipe is built on, and what `test_ShadowRingBuffer` reads and writes across. `CTaskPipe`/`CPartPipe` are NOT YET.

The NewtonScript half of the boot is `frames/ScriptBoot.h` (`InitScriptGlobals`: `gVarFrame` rebuilt on the ROM's starter map, `vars.classes` and `vars.functions` set, then the ROM's own boot block `Rbootinitnsglobals` run; `RunInitScripts` runs `Rbootruninitscripts`), and `host/HostNatives.h`'s `RegisterAllNatives` binds every reconstructed native in one place - each area registers its own, but only three of thirteen were being called, so ROM scripts failed on functions that existed. To find the next thing the boot needs: `build/host/host/newtonscript --rom <image> -e 'call ROMConstant("bootinitnsglobals") with ()'` - an unbound native names itself on stderr (and, with `NEWTON_TRACE_MISSING` set in the environment, prints the script stack that asked for it - which is how to tell which of the ROM's own functions wants it).  `NEWTON_TRACE_EXCEPTIONS` does the same for the object system's exceptions: `ThrowRefException` prints the exception, what it carries and the script stack *at the throw*, which is the only place the stack still stands - by the time a handler reports it the interpreter has unwound.  That is how a mistake in one of the ROM's own scripts is tracked back to the script that made it. That block runs to the end, and `TNotebook::InitToolbox` runs it as the ROM does, so booting `build/host/host/newton` mounts the store, creates the System soup, builds `vars.userConfiguration` out of it and sets the sort id, the contrast and the system volume. `TNewtWorld::MainConstructor` calls `InitializeCompression` first, as the ROM does: with the OS running a store cannot write an object without the compressors in the protocol registry, because `NewCoder` then makes them by name rather than straight off their class info. `analysis/nsfunctions.py build/MP2x00US --disasm 0x1db` disassembles a ROM function by its magic-pointer ref (the REP prints one as `#1DB`), which is how the blocks the boot calls were read. `src/pcmcia/` holds the card side (only `FGetCardInfo` so far, which that boot block asks for) and `src/system/` what a script may ask of the machine itself (`SystemNatives.h`: `GetSerialNumber` over `hal/System.h`'s `GetSystemSerialNumber`, the host having a fixed number of its own where the Newton reads a one-wire chip; `GetHeapStats` over the pointer, handle and frames heaps (`docs/memory/README.md`: the host's `TotalSystemFree` answered 0 until it had someone to ask); the battery, backlight and power functions are NOT YET - and `ConfigServer.h`: `TNSConfigServer`, protoConfigServer's C++ side, which `CSInstantiate` hangs off the script's `ciPrivate` slot, keeping the service's four characters and the configuration's name; `GetConfig`/`SetConfig`/`Dispose` over `TUConfigServer` (`os600/user/UserConfigServer.cpp`), which is the name server under another name: a service's default configuration is registered under the service's four characters). `TNotebook::InitToolbox` then runs `RunInitScripts`, which asks each installed part for its InstallScript - that is what makes the ROM's thirteen soups. The host runs the OS with one thread per task, only `gCurrentTask`'s running; system-call stubs (`os600/user/host/SWI.cpp`) call the kernel glue and then `HostSWIExit` (`os600/kernel/host/TaskRuntime.cpp`), the C form of SWIBoot's exit path — see `docs/host-runtime.md` before touching either. Task registers are `TRegister` (pointer-sized); read ids/selectors out of them with a `(ULong)` cast.

## Reverse-engineering notes

`docs/next-steps.md` says where the last piece of work left off and what is next; read it when picking the work up again, and keep it current as pieces are finished. RE findings go under `docs/<subsystem>/` (kernel: `docs/os600/`). Tables derived from the ROM must be produced by a script in `tools/newton-rom/analysis/` (e.g. `swi_table.py` → `docs/os600/swi-table.md`) and say so in their header, so they can be regenerated after a re-import; hand-written pages state how each fact was established. Kernel-side classes (`TTask`, `TPort`, `TObjectTable`, …) have no DDK headers; only the user-side `TU*` API does.

## Working with the repository files

- **Header files use classic Mac CR-only line endings (`\r`).** `grep`/`head`/`sed` see one giant line; pipe through `tr '\r' '\n'` first, e.g. `tr '\r' '\n' < headers/OS600/ROMExtension.h | grep kRExSignature`.
- `tools/mpdumper` (2004, Cygwin): options must be combined (`mpdumper -dx <image>`, not `-d -x`); the `.exe` needs the bundled `cygwin1.dll`. Its `Symbols_demangled_by_address.txt` (`Code symbol: Name = HEXADDR`) is the demangler oracle — grep it or `build/MP2x00US/symbols.txt` (`ADDR class mangled demangled`) instead of re-deriving symbols.
- ROM images and symbol files are multi-MB; use `xxd`/`grep`/ranged reads or the `newtonrom` library rather than reading them whole.
