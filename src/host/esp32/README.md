# src/host/esp32 - the reconstruction on an ESP32-S3 (the LilyGO T-Deck Pro)

An ESP-IDF application, built with PlatformIO, that runs the reconstructed
Newton on the T-Deck Pro (`docs/host-tdeck-pro.md` is the investigation
and the plan).  **Milestone B**, where it stands: the OS booted on the
board - the ROM's objects mapped from flash as a baked image, the kernel
and its tasks on FreeRTOS, the newt world with a 240x320 one-bit display
**on the e-paper panel**, **the touch panel as the pen and the keyboard as
the keyboard**, and **the internal store on the board's flash, kept
between starts** - with a NewtonScript prompt on the USB serial port, each
line evaluated in the newt world.

## What is here

| File | What |
|---|---|
| `platformio.ini` | the build: `espressif32@6.5.0` (ESP-IDF 5.1), the DevKitC-1 board with 16 MB of flash, `upload_speed` 115200 (the board's own USB port has no baud rate, and esptool's change of it failed) |
| `sdkconfig.defaults` | quad PSRAM (not octal, whatever LilyGO's README says), `malloc` reaching it, task stacks allowed in it, the USB serial/JTAG console, quad flash at 80 MHz, a 64 KB data cache with 64-byte lines, C++ exceptions and RTTI, `-O2`, no task watchdog, a 1 ms tick |
| `partitions.csv` | the program (6 MB), the baked ROM objects (`objects`, 5.9 MB at 0x610000), the Newton's 4 MB internal flash (`store`, at 0xC00000) |
| `upload_objects.py` | writes `objects.baked` (or `NEWTON_BAKED_IMAGE`) to the `objects` partition with every upload |
| `main/CMakeLists.txt` | the one component: the tree's sources with the desktop's flags (`forQ`, `host_compat.h` first, `-fwrapv`, `-fsigned-char`, `-falign-functions=4`), each source with its own include directories as `-iquote` |
| `main/newton_sources.cmake`, `main/forwarded/` | generated by `tools/tdeck/idf_sources.py` (below) - regenerate, don't edit |
| `main/esp32main.cpp` | the board's side (ESP-IDF's headers only): the console made a blocking stdio stream read by a task of its own into a queue of lines, the `objects` partition mapped at 0x3d000000, the Newton's tasks' threads (FreeRTOS tasks with 48 KB stacks in PSRAM, all on core 1) |
| `main/tdeck_panel.cpp` | the panel (a task on core 0): the display's grays watched and sent to the UC8253 once a change settles - a partial refresh (0.65 s) over the rectangle that changed, a new page included; a full one (3 s, flashing) to clean up the ghosts after 30 s still, or after 30 partial ones at the first 2 s pause - either only once the partial ones have redrawn 5 % of the screen between them, so a clock's minute alone never flashes it, and less than that is cleaned up over the rectangle redrawn by flipping it and back after 10 partial ones (`localClean`); how the controller has to be driven, and how that was found, is its header's; settings changed while it runs: `DevicePanelSet(name, value)` |
| `main/tdeck_input.cpp` | the CST328 touch panel and the TCA8418 keyboard (a task on core 0, a hundred times a second) into the window shims every host's window calls (`HostWindowPenDown/Move/Up`, `HostWindowKey`, host/HostKeyboard.cpp); the owner's keyboard layout (Shift, Sym's symbols, Alt's navigation keys or the Command key); a finger pulled down from the top edge is the quick sheet's pull, and the keyboard is left out while the screen is locked ("The quick sheet and the lock screen", below) |
| `main/tdeck_battery.cpp` | the battery: the BQ27220 fuel gauge (0x55: charge, voltage, current, temperature, whether one is fitted) and the BQ25896 charger (0x6B: USB power good, charging or done) on the input's I2C bus, given to power/host/HostBattery.h as the board's source - `BatteryStatus(0)` is the board's; the gauge stretches the clock as it wakes, so the bus's timeout is 13 ms (`tdeck_input.cpp`) |
| `main/tdeck_store.cpp` | the Newton's internal flash on the `store` partition: mapped read-only and read in place by hal/host/HostFlash.h (its backing - no copy in RAM), each run of words the store's driver writes (hal/host/HostFlash.h HostFlashBeginRun) and each erase done by a writer task whose stack is in internal RAM (a task with a PSRAM stack must not write the flash), the mapping's cache refreshed after; erased whole the first time (NVS `storeVersion`); a self-test of write, lanes erase and sector erase at each start |
| `main/tdeck_gps.cpp` | the GPS receiver (a u-blox MIA-M10Q: power GPIO 39, UART2 on GPIO 44/43, 38400 baud or else 9600; "The GPS on" switches GPIO 39, kept as `gpsOff`), given to hal/host/HostGPS.h as its source `device`: `HostGPSStatus()` has its fix (the Mesh application's location) and a Newton GPS application on serial port 2 its sentences |
| `main/tdeck_lora.cpp` | the LoRa radio (the SX1262 on the panel's SPI bus): RadioLib through a HAL of the board's own, given to hal/host/HostMesh.h's MeshCore node, run on a task of its own (PSRAM stack); a keeper task with an internal stack does the node's NVS blobs and the power switch (GPIO 46, "The LoRa radio on", kept as `loraOff`) - docs/host-tdeck-pro-mesh.md |
| `main/tdeck_wifi.cpp` | the WiFi: networks remembered in NVS (up to 8), the strongest remembered one in range joined (and again 30 s after it is lost or none is found), scans on request - the provider of host/HostWifi.h, which Internet Setup's Host network setup has a Wi-Fi line and slip for (comms/host/HostLink.ns); a task of its own with an internal stack does the work (NVS writes the flash) |
| `main/tdeck_profile.cpp` | a sampling profiler of core 1 (the Newton's tasks), from the board's start: `DeviceProfileDump()` prints it for tools/tdeck/profile.py |
| `main/newtonmain.cpp` | the Newton's side (the DDK's headers only): the kernel heap (3 MB, in PSRAM) with a 1 MB NewtonScript heap, the baked objects, the newt world configured (240x320x1, the store in RAM) and the OS booted; the kernel services task hands each console line to the newt world as a `'host/'eval` event, whose handler evaluates it and prints the result; `DeviceMilliseconds()`, `DeviceMemory()`, `DevicePanelSet(name, value)` and `DeviceStore()` ([words written to the store partition, erases]) for NewtonScript; every NewtonScript throw printed with its script stack (`NEWTON_TRACE_EXCEPTIONS`, set there) |

The tree's own platform code has `ESP_PLATFORM` branches where it must:
`os600/kernel/host/TaskRuntime.cpp` (a task's thread is a FreeRTOS task
the board's side makes), `hal/host/System.cpp` (the stack's bounds from
FreeRTOS; a reset prints a backtrace), `hal/host/HostSockets.cpp` (lwIP:
no interface list, no reverse lookup, no signals).  `malloc(0)` answers a
block, as the desktops' do (newlib's answers nil; `__wrap_malloc` in
esp32main.cpp).  Everything else is the tree as the desktop builds it,
host/HostKeyboard.cpp included (the key queue and the window's shims;
the kernel services task sends the keys with `HostKeyboardSendKeys`).

## Building and running

Everything comes from PlatformIO (`~/.platformio`); on Linux and macOS
`penv/bin/` for `penv/Scripts/`.

1. **The source list**, when sources have been added to or taken from the
   tree: from a 32-bit build's compile commands (the desktop's per-library
   include directories and flags are what it copies):

        cmake -G Ninja -S src -B tmp/build-arm -DCMAKE_TOOLCHAIN_FILE=$PWD/src/cmake/zig-arm-linux.cmake \
            -DCMAKE_BUILD_TYPE=MinSizeRel -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \
            -DNEWTON_HOST_NEWTONSCRIPT=$PWD/build/host/host/newtonscript.exe
        python tools/tdeck/idf_sources.py tmp/build-arm/compile_commands.json

2. **The program**: `~/.platformio/penv/Scripts/pio run -d src/host/esp32`
   (the first build installs ESP-IDF - see tools/tdeck/README.md; after
   that about 20 s for a change, a few minutes for everything).
   **A changed `.ns` file embedded in the program** (`main/CMakeLists.txt`'s
   EmbedText rules: HostMesh.ns, HostMessages.ns, HostSettings.ns, ...) is
   not embedded again by PlatformIO's build, though CMake is told to
   reconfigure for it (`CMAKE_CONFIGURE_DEPENDS`): touch
   `main/CMakeLists.txt` first, or the board runs the old one (found
   2026-10-14: the Mesh application without its newest methods).

3. **The baked ROM objects** (`frames/ROMImport.h`): made by the 32-bit x86
   build (`src/cmake/zig-x86-linux.cmake`, run under WSL 2 or Linux; its
   layout is the ESP32-S3's) for the address the board maps the `objects`
   partition at, 0x3d000000 (`esp32main.cpp`'s `MapObjects`: ESP-IDF
   would put it after the program's own mappings and the PSRAM's, which
   move as the program grows, so the space below 0x3d000000 is filled
   first - 4 MB of room for the program to grow in):

        tmp/build-x86/host/newton --objects build/host/romsrc-objects.bin \
            --bake-objects src/host/esp32/objects.baked --bake-base 0x3d000000

   A board given an image baked elsewhere, or by a build of another layout,
   says so and starts without the ROM's objects.  Bake again whenever the
   object file or the frames layout changes.

4. **Onto the board**: `~/.platformio/penv/Scripts/pio run -d src/host/esp32 -t upload --upload-port COM4`
   - the program and, when it is there, `objects.baked`.  If esptool stops
   with "No serial data received" after the stub starts, the board needs
   power taken off it (the USB cable out, the battery out) and back.

5. **The prompt** ("the OS is up", about a minute after the start): any
   serial terminal on the port, or from a script:

        ~/.platformio/penv/Scripts/python tools/tdeck/serialcapture.py COM4 120 --reset \
            --after "the OS is up" --send "2 + 3;" --send "DeviceMemory();"

   PlatformIO does not notice that `main/newton_sources.cmake` changed:
   touch `main/CMakeLists.txt` after regenerating it.  For a heap that
   seems damaged, `CONFIG_HEAP_POISONING_COMPREHENSIVE=y` in
   `sdkconfig.defaults` (delete `sdkconfig.tdeck-pro` so that it is read
   again) checks each block's ends when it is freed.

## The 4G module (2026-10-12)

`main/tdeck_modem.cpp` powers the A7682E (supply GPIO 41, power key GPIO
40) and hands UART1 (TX 10, RX 11, 115200) to the portable engine,
`hal/host/HostCellular.h`, on a task of its own; the network's time sets the
board's clock.  **The module needs the battery fitted** - its supply runs
from it; on USB alone it stays dark.  From the prompt:

    HostCellStatus();                  // {state: home, operator: ..., rssi: -77, ...}
    HostCellCommand("ATI");            // any AT command, its reply lines

The plan and what the module said: `docs/host-tdeck-pro-phone.md`.

## WiFi (2026-10-11)

Internet Setup's **Host network** setup has a **Wi-Fi** line on the board:
its slip lists the networks the board sees, takes a password, and Join
remembers the network chosen (the board joins it now if it is in range,
and whichever remembered network it finds from then on); Forget forgets
it.  Once joined, the NIE's TCP and DNS go out through lwIP.  From the
console: `HostWifiScan()`, `HostWifiKnown()`, `HostWifiRemember(ssid,
password)`, `HostWifiForget(ssid)`, `HostWifiStatus()` (host/HostWifi.h).

The board starts the host's link for the NIE (comms/host/HostLink.h) in
its PreMain, as the desktop does - without it Internet Setup finds no
module and will not open; HostLink.ns is compiled in when CMake configures
(PlatformIO runs no custom commands).  ESP-IDF's event task has a 4 KB
stack: 2304 bytes overflowed when an address was got.

**The small screen** (2026-10-12; all DEVIATIONs, none changing what a
MessagePad shows): an application that wants more than 320 high is no
longer asked to turn the screen when it is upright already - turning it
to upright changed nothing, and the OK rebuilt the display (and put up
the button bar's "couldn't hold all the icons") for nothing
(`viewRoot.Open`, `romsrc/objects/system/viewRoot.ns`).  Internet Setup's edit slip
takes the bounds its walk-through layout has, which fit the screen, and
its keyboard is the slip's width (`romsrc/rex/inetstup/README.md`); the
Typewriter keyboard is the screen's width where its small size will not
fit (`alphaKeyboard.viewSetupFormScript`) - a keyboard view makes its
keys to fit its bounds.  The slip that asks for what a worksite or the
owner's card is missing (`ValidateConfig`: Time Zones' "This worksite is
incomplete.  Please choose the closest city", 284 wide) is the screen's
width, its keyboard too (`protoValidateSlip.viewSetupFormScript`,
`viewSetupChildrenScript.ns`).

**The keyboard is built in**, as an eMate 300's is: the board answers the
keyboard gestalt (`kGestalt_Extended_Base + 10`, `newtonmain.cpp`'s
DeviceBoot), so the root view takes a keyboard as connected from the
start (`KeyboardConnected()` is true) and the system leaves out the
on-screen keyboards it would put up by itself (Internet Setup's slips)
- the Typewriter is still there when asked for (a keyboard button, the
Notes' keyboard icon).

Other applications that will not open at 240x320 upright ask to turn the
screen.  The board follows the Newton turned to landscape - the panel
draws the display a quarter turn round (hold the board turned clockwise,
the keyboard on the left), the touch panel turned back - and the Newton
then asks for its pen to be calibrated for the new way round, as a
MessagePad does.  On a fresh store the Setup assistant, as the backdrop,
refuses to turn: go through Setup first.

Room for it: WiFi wants internal RAM, which the tree's static data had
filled - the six largest statics (HostIPP's buffer, the tablet's ring,
the colour table, the unistroke templates, DNS-SD's results, the screen's
expansion table: 200 KB) are `HOST_LARGE_STATIC` (host/host_compat.h:
PSRAM on the board), with `CONFIG_SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY`
and the WiFi's and lwIP's buffers in PSRAM.  162 KB of internal RAM is
free at the start, 53 KB with the OS up (13 KB before).

**The clock**: the board has none that keeps time while it is off, so it
starts at 1970 (the Newton's 31/12).  Once a network is joined, SNTP
(`pool.ntp.org`, polled hourly by ESP-IDF) sets the board's clock, and
each time it does, the Newton's is set from it
(`TURealTimeAlarm::SetTime`, in GMT; the Newton shows its home city's
time) and the console prints `newton: the clock set: ...`.

**The board's own console commands**, answered whatever the Newton is
doing: `!shot` prints what the panel shows (`tools/tdeck/panelshot.py`
makes a PNG of it), `!prof` the profile, `!time <seconds since 1970,
GMT>` sets the clock by hand (as a sync from the network does), `!tap <x>
<y>` puts the finger on the display there for 100 ms (a modal dialog,
which stops the NewtonScript console, answered from it), `!reset`
restarts the board.

## A faster start (2026-10-11)

The OS is up **3.2 s** after the boot starts (a minute before): the
panel shows the Newton about 6 s after power-on (the bootloader, and 1.5 s
left for a terminal to open the console).  What the profiler found
(tools/tdeck/profile.py; docs/host-tdeck-pro.md, "A faster start"):

- **C++ throws took 22 ms each** - Espressif's libgcc does not sort the
  exception tables unless asked (`_Unwind_SetEnableExceptionFdeSorting(1)`,
  esp32main.cpp), and the task runtime throws at many task switches: 78%
  of the minute.  Now 62 µs.
- **The ROM extensions' headers** were searched for in the baked image (in
  flash) at every call: packages/ROMPackages.cpp remembers the answers.
- **Native functions and ARM glue were registered by comparing each name
  with every entry** (~2,000 and ~2,900): frames/NativeFunctions.cpp and
  armcpu/PackageNativeCPU.cpp index them by a hash of the name.

## The store (2026-10-11)

The internal store is the ROM's flash store on the Newton's 4 MB internal
flash, which is the `store` partition (tdeck_store.cpp) - mounted, formatted
when new, kept between starts, as the desktop's `--store` file is.  The
first start after the partition is made erases it (11 s) and formats the
store; a later one finds it used before (with the start made faster, the
OS up in about 3 s).  An entry added to a soup reads back after a reset.
Writes are synchronous from the Newton's task; since 2026-10-13 a whole
run of words the store's driver writes goes over in one hand-over and one
`esp_partition_write` a sector, not one a word - adding ten Names cards
went from about 420 ms to 250 ms, removing them from about 315 ms to 190 ms
(`tools/tdeck/storebench.py`; docs/host-tdeck-pro.md, "Batched store
writes").

## The panel, touch and keyboard (2026-10-11)

The panel shows the Newton cleanly; typing and taps update only what
changed.  Settings (`DevicePanelSet`, while it runs; tdeck_panel.cpp lists
them): `trace` (each refresh's kind, time and rectangle on the console),
`bigChange`, `cleanAfter`, `cleanCount`, `cleanPause`, `cleanArea`, `localClean`, `partialTemperature`, `fullTemperature`,
`redraw`, `test` (a test pattern - tools/tdeck/panelprobe.py photographs
it), and the controller's set-up ones kept for comparing.  The ones a user
would change - a new page drawn in full, the two clean-ups, Clear ghosts,
and the 4G module switched off to save the battery (tdeck_modem.cpp) -
are on the Newton's own Prefs too - the panel's on the Screen page, the
4G module on the Host page (host/HostSettings.cpp, docs/host-settings.md;
kept in the System soup).  Touch arrives in
the panel's pixels; the Newton's own pen calibration takes out a finger's
offset.

## The quick sheet and the lock screen (2026-10-16)

As the owner's lilyphone1 firmware had: **a finger pulled down from the
screen's top edge** opens a sheet across the top - "Lock screen", and a
checkbox each for the 4G module, the GPS and the LoRa radio (only those
the board can switch) - and **Lock screen** covers the whole screen with
the time, the date and a slider whose knob is dragged from its left end
to the right to unlock.  The NewtonScript is host/HostQuickSheet.ns
(host/HostQuickSheet.h; installed on every host since 2026-10-25, ctest
`host.NewtonQuickSheet`).  Since then the lock screen also holds the
notifications applications leave on it while it is locked, and locks by
itself after the Host page's **Auto-lock** (docs/host-lock-screen.md).

- **The pull** (tdeck_input.cpp): a finger landing within 14 px of the top
  is held back from the Newton until it shows what it is - 40 px down is
  the pull (none of it reaches the Newton; `HostDeviceSheetPulled`, which
  the kernel services task turns into `HostQuickSheetPulled` in the newt
  world); lifted first it is a tap where it landed; moved 16 px sideways,
  or held 300 ms without coming down, it is the pen's from where it
  landed.  So a button at the very top still answers a tap, a press held
  on it a third of a second late.  Pulled while the sheet is open, the
  sheet closes.
- **The switches** are the Host preferences panel's `cellPower` and
  `gpsPower` (changed through its frame, so kept as if changed there) and
  the Mesh application's `HostMeshSetPower` (the board keeps it in NVS).
- **Locked**: the lock screen is a floating view over everything; a press
  that does not start on the knob does nothing, and the knob let go short
  of the end goes back, so a tap (a pocket) cannot unlock it.  The board
  is told (`HostScreenLocked` → `HostDeviceSetLocked`): the keyboard's
  presses are left out (a release still goes, for a key pressed before)
  and its light is off; the top edge is the pen's like the rest of the
  screen.  The time is redrawn when the minute changes, not before.
- From the console: `GetGlobalVar('|QuickSheet:host|):Pulled()`, `:Lock()`,
  `:Unlock()`; `!shot` and tools/tdeck/panelshot.py show what the panel
  was sent.
- A view opened with `:Open()` must not have `vVisible` in its template's
  viewFlags: `TView::Show` (the ROM's) does nothing for a view visible
  already, so it is never drawn (found here: a template with 581 opened
  but stayed off the screen; 580, as the ROM's floaters have, is drawn).
  And the ROM's protoClosebox closes `base`: a view of one's own that has
  one must say `declareSelf: 'base`, or its close box does nothing.

## What it measured (2026-10-11, the owner's V1.0)

Milestone B (the OS booted):

- The program is 4.0 MB; 285 KB of the internal RAM is static data
  (87%), 29 KB is free with the OS up, and 2.6 MB of the PSRAM.
- Start: the kernel and its tasks in 10 s, the newt world in another
  17.5 s ("Welcome to NewtonScript!"), the OS up - `gNewtIsAliveAndWell`,
  the built-in applications installed - 62 s after the start.
- NewtonScript as fast as at milestone A (the 100,000-pass loop 445 ms);
  `GetRoot().viewBounds` is 240x320; one store.

Milestone A (NewtonScript alone):

- The program is 2.76 MB; 128 KB of the internal RAM and 5 MB of the
  PSRAM are free with the REP running.
- Start: the baked objects in 11 ms (mapped, not read), the object system
  in 0.7 s, the natives in 1.1 s.
- NewtonScript (`DeviceMilliseconds`): a 100,000-pass integer loop 437 ms;
  2,000 strings made and stored 979 ms; 2,000 integers made and sorted
  49 ms - about 120, 500 and 80 times the 32-bit desktop build's time on
  the development machine.  The processor alone accounts for most of the
  first and last; the allocation-heavy one is the PSRAM's cache misses
  (docs/host-tdeck-pro.md).
