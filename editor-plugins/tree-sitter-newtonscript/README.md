# tree-sitter-newtonscript

A [tree-sitter](https://tree-sitter.github.io/) grammar for NewtonScript,
the Newton's object-oriented scripting language. It is used by the Zed
extension in `../zed-newtonscript`, and any other tree-sitter editor
(Neovim, Helix, Emacs) can use it too.

## Where it comes from

The grammar is taken from the Newton's own compiler rather than from the
manuals:

- the tokens from the reconstructed lexer, `TCompiler::yylex0`,
  `GetNumber` and `GetCharsUntil` (`src/frames/Lexer.cpp`);
- the rules from the ROM's yacc grammar, `docs/frames/grammar.md`
  (generated by `tools/newton-rom/analysis/nsgrammar.py` from the 2.1
  ROM's `yyrule` table);
- the precedences from the ROM's yacc tables, which agree with the
  NewtonScript Reference's operator table.

Rules the compiler follows that a reader might not expect, all mirrored
here:

| What | Why |
|---|---|
| Reserved words, `nil` and `true` ignore case (`IF x THEN nil`) | `ReservedWordToken` compares as symbols compare (`symcmp`) |
| A semicolon may come before `end`, `else`, `until`, `onexception`, `)`, `]`, `}` or `,` | `TCompiler::GetToken` drops it |
| A comma may come before `]` or `}` | `GetToken` drops it too (not before `)`) |
| `1e5` is the integer 1 followed by the symbol `e5` | a real needs its point (`GetNumber`) |
| `"a" "b"` is one string | `GetCharsUntil` carries on into the next string after white space |
| In a string, `\u` starts and ends a run of four-digit hex UniChars | `GetCharsUntil` |
| `[x: ...]` is an array of class `x`, never a send to `x` | yacc shifts the `:` |
| `'a.b.c` is one quoted path | yacc shifts the `.` |
| `foreach v in x collect v`: the verb is any symbol | `withverb : tokenSYMBOL` |

Where the grammar is more lenient than the compiler: a type is accepted
before any local in a `local` list, not only the first, and `; else` is
lexed as one token, so `; elseX` (a symbol beginning with "else" after a
semicolon) is misread - the compiler needs two tokens of lookahead there,
which an LR(1) grammar does not have.

Three things that are not NewtonScript are accepted because the
repository's NewtonScript is written with them:

- `#1a3`, an immediate Ref in hex - how the REP prints one and how
  `romsrc/` writes one (`tools/newton-rom/analysis/romsrc.py`'s notation);
- `@@ ...` record lines (`@@ 0x3c5b25`, `@@const name`, `@@main`,
  `@@end`), which divide a `romsrc/functions/` file into records;
- `#line n "file"`, which the compiler does accept.

## Building and testing

Needs Node.js (for the tree-sitter CLI) and a C compiler (the CLI builds
the parser to run it; on Windows, the Visual Studio build tools).

```sh
cd editor-plugins/tree-sitter-newtonscript
npm install                    # the tree-sitter CLI, into node_modules/
npx tree-sitter generate       # grammar.js -> src/parser.c (committed)
npx tree-sitter test           # the corpus in test/corpus/
python check_repo.py           # every *.ns file git tracks
```

`check_repo.py` parses every NewtonScript file in the repository - the
ROM's NewtonScript world in `romsrc/`, the host's demos, about 7000
files - and prints each one that fails with its first error's line
(`--show N` for more than 20; paths as arguments to check only those).
At the time of writing all of them parse.

`src/` is generated and committed, because an editor builds the parser
from `src/parser.c` without running the CLI: run `npx tree-sitter
generate` after any change to `grammar.js` and commit both, then update
the `rev` in `../zed-newtonscript/extension.toml` (see its README).

The highlight query lives with the Zed extension
(`../zed-newtonscript/languages/newtonscript/highlights.scm`);
`tree-sitter.json` points there so there is one copy.
`npx tree-sitter query <file.scm> <file.ns>` checks a query compiles
against the grammar and shows what it matches.
